## Entity Resolution Pipeline

**File:** `personal_ingest_api.py` — `resolve_entity()` function (~line 693)

**5-tier resolution:**
1. **Tier 1** — Exact match on normalized text → 1.0 confidence
2. **Tier 1.1** — Registered alias match → 1.0 confidence
3. **Tier 1.5** — Contextual co-occurrence with associated people
4. **Tier 2a** — Jaro-Winkler fuzzy match (threshold per entity type)
5. **Tier 2b** — OpenAI embedding cosine similarity (pgvector)
6. **Tier 3** — Create new entity

**Key schema config** (`entity_schema.py`, `DEFAULT_SCHEMAS`):
- `Person`: `similarity_threshold=0.92`, `require_token_overlap=False`, `phonetic_matching=True`
- `Organization`: `similarity_threshold=0.90`, `require_token_overlap=True`
- Most types: `require_token_overlap=True` (default)

### Known False-Merge Risk: Person First-Name Inflation

**Problem:** Jaro-Winkler gives artificially high scores when two names share a long common prefix (e.g., "Benjamin"). `require_token_overlap=False` for Person meant the multi-word token overlap guard was bypassed entirely.

**Example:** `JW("benjamin life", "benjamin neal") = 0.9203 ≥ threshold 0.92` → false merge.

**Fix (commit `8c067644`):** Added last-name gate in the policy now named `passes_token_overlap_strict()`:
- For 2-token names where `require_token_overlap=False`, requires `JW(last_token_1, last_token_2) >= 0.75`
- "life" vs "neal" → JW ≈ 0.4 < 0.75 → **rejected**
- "life" vs "life" (Ben Life / Benjamin Life) → JW = 1.0 → **still passes**

**Remediation script:** `scripts/split_false_merges.py` — splits known collision pairs in the local `personal_koi` DB. Pre-populated with known collisions. Run with `source config/personal.env && python scripts/split_false_merges.py [--dry-run]`.
