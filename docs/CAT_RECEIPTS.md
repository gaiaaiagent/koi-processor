# CAT Receipts (Content Addressable Transformation)

## Overview

CAT receipts provide complete provenance tracking for all data transformations in the KOI pipeline. Every time content is processed, transformed, or enriched, a cryptographic receipt is created that forms an immutable audit trail.

## What are CAT Receipts?

CAT (Content Addressable Transformation) receipts are cryptographic records that track:
- **Input**: What content entered the transformation (RID, CID)
- **Output**: What content was produced (RID, CID)
- **Processor**: Which component performed the transformation
- **Metrics**: Processing statistics (chunks, embeddings, duration)
- **Metadata**: Additional context and parameters

## Receipt Types

The KOI pipeline generates several types of CAT receipts:

### 1. `koi_to_memory`
Created when raw sensor data is chunked and stored as memories.
- Input: Original document RID
- Output: Chunk RIDs
- Tracks: Number of chunks created

### 2. `memory_to_bge_embedding`
Created when text chunks are converted to BGE embeddings.
- Input: Memory chunk RID
- Output: Embedding identifier
- Tracks: Embedding model and dimensions

### 3. `koi_event_processing`
Overall receipt for complete event processing.
- Input: Event RID
- Output: Processed RID
- Tracks: Total chunks and embeddings created

## Database Schema

CAT receipts are stored in the `koi_transformation_receipts` table:

```sql
CREATE TABLE koi_transformation_receipts (
    receipt_id VARCHAR(64) PRIMARY KEY,       -- SHA-256 hash
    transformation_type VARCHAR(100),         -- Type of transformation
    input_rid VARCHAR(255),                   -- Input Resource ID
    input_cid VARCHAR(255),                   -- Input Content ID
    output_rid VARCHAR(255),                  -- Output Resource ID
    output_cid VARCHAR(255),                  -- Output Content ID
    processor_name VARCHAR(100),              -- Processing component
    processor_version VARCHAR(50),            -- Component version
    chunks_created INTEGER DEFAULT 0,         -- Chunks created
    embeddings_created INTEGER DEFAULT 0,     -- Embeddings created
    source_sensor VARCHAR(100),               -- Source sensor name
    event_type VARCHAR(50),                   -- NEW, UPDATE, FORGET
    metadata JSONB DEFAULT '{}',              -- Additional metadata
    created_at TIMESTAMP WITH TIME ZONE,      -- Creation timestamp
    processing_duration_ms INTEGER            -- Processing time
);
```

## Querying CAT Receipts

### View Recent Receipts
```sql
SELECT
    transformation_type,
    input_rid,
    output_rid,
    chunks_created,
    embeddings_created,
    created_at
FROM koi_transformation_receipts
ORDER BY created_at DESC
LIMIT 10;
```

### Get Complete Provenance Chain
```sql
-- Use the built-in function to trace provenance
SELECT * FROM get_provenance_chain('your.rid.here');
```

### Find Processing Statistics
```sql
SELECT
    transformation_type,
    COUNT(*) as receipt_count,
    SUM(chunks_created) as total_chunks,
    SUM(embeddings_created) as total_embeddings,
    AVG(processing_duration_ms) as avg_duration_ms
FROM koi_transformation_receipts
WHERE created_at > NOW() - INTERVAL '24 hours'
GROUP BY transformation_type;
```

## Implementation Details

### Receipt Generation

CAT receipts are automatically generated by the Event Bridge v2 when:
1. A KOI event is processed into memory chunks
2. Text chunks are converted to embeddings
3. Overall event processing completes

### Receipt ID Generation

Receipt IDs are SHA-256 hashes of:
- Transformation type
- Input RID
- Output RID
- Timestamp

This ensures unique, deterministic IDs for each transformation.

### Error Handling

If CAT receipt creation fails, it doesn't block the main processing pipeline. Errors are logged but processing continues to ensure data flow isn't interrupted.

## Monitoring CAT Receipts

### Check Receipt Generation Status
```bash
psql $DATABASE_URL -c "
SELECT
    DATE(created_at) as date,
    COUNT(*) as receipts_created
FROM koi_transformation_receipts
WHERE created_at > NOW() - INTERVAL '7 days'
GROUP BY DATE(created_at)
ORDER BY date DESC;
"
```

### Verify Pipeline Health
```bash
psql $DATABASE_URL -c "
SELECT
    transformation_type,
    COUNT(*) as count,
    MAX(created_at) as last_created
FROM koi_transformation_receipts
GROUP BY transformation_type;
"
```

## Troubleshooting

### No Receipts Being Created

1. Check if the primary key constraint exists:
```sql
SELECT constraint_name FROM information_schema.table_constraints
WHERE table_name = 'koi_transformation_receipts'
AND constraint_type = 'PRIMARY KEY';
```

2. Run migration if needed:
```bash
./scripts/run_migrations.sh
```

3. Verify Event Bridge is using the updated code with CAT receipt creation.

### Missing Provenance Data

If receipts exist but provenance queries return no results:
1. Check that both input and output RIDs are being recorded
2. Verify the get_provenance_chain function exists
3. Ensure receipts are being created for all transformation types
